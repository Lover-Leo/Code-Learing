### 2026-10-16 新知识与纠正

- lambda 是可调用对象，Predicate 推导的是它的类型，predicate 是函数形参；不要求模板参数只能是 int/double。
- const 引用形参限制通过该引用修改实参；成员函数尾部 const 限制修改对象普通成员；返回 const 引用限制通过返回引用修改数据，不延长数据寿命。独立函数不能尾部 const。只读对象调用实验用户自报理解，未保留独立测试。
- 类中实际容器名是 values。助手曾在未看到成员声明时误判名称，已纠正；之后评审先核对声明。
- 值捕获保存副本；引用捕获借用原对象，可看到后续变化但必须保证生命周期。返回 lambda 引用捕获局部参数会悬空。makeAbove 只讲解，用户确认理解并跳过实现，不执行悬空访问实验。

### 本次澄清与纠错

- main 开头的 return 0 导致后面不可达；解析坏行时 return 1 会退出 main，应跳过本轮；提取 analyze 后循环内多余 return 又导致只读第一行，现已移除。return 结束函数；continue 进入下一轮；switch 中 break 只退出 switch。
- “解析函数”是用途名称，不是特殊语法；把文字转成记录或错误。流条件检查读取状态，不是检查数值是否为零；测试文件中的 wrong/extra 是故意设计的错误。
- using 是类型别名，#define 是预处理文字替换；struct 默认 public、class 默认 private。未写构造函数仍可能因私有成员而无法进行这里的大括号聚合初始化。
- variant 改为保存 PraseError 后，必须 get<PraseError> 再访问 message，不能继续 get<string>。助手曾仅根据级联报错猜测 void 输出；保存后检查源码才确认真正问题，后续不要对未保存截图过度推断。
- get_if 得到的是 result 内部对象的借用指针，不接管所有权。用户口头答对 nullptr 时 && 短路、不访问成员；独立解析成功测试按用户要求跳过，未计为运行通过。
- map<string,double> 取出的是数字，不能 push_back；分组必须 map<string,vector<double>>。records 数记录，groups 数名称；用户最初没看到追加数据，已澄清为 4 与 2。
- 结构化绑定的 [name,values] 不是 lambda 捕获；ostream 与 ofstream 不同，前者接口可借用不同输出流；输出流不能加 const，读取数据可用 const 引用。
- ostringstream 和普通 string 一样在运行时内存中保存内容，不自动显示或落盘；str() 返回文字副本，不清空流。
- 自动测试使用事先可人工算对的小样例，检查功能及以后修改，不要求预知全部真实输入。用户理解这一点；单个 true 不代表整个项目和所有边界通过。

## 6. 后续讲解容易混淆的点

- 指针变量、容器元素和实际对象是不同层次；auto 推导由表达式类型决定，不会自动选择基类。
- 基类指针/引用不改变实际对象类型；按值构造基类才可能切片。
- unique_ptr 的空状态在移动后有保证，不应推广到所有类型的移动后内容。
- std::move 是转换表达式；绑定 && 本身不等于接管；转换成不同 unique_ptr 类型可能构造新拥有者，应结合具体参数类型解释。
- shared_ptr::reset 不一定销毁对象；只释放当前这份所有权。
- 不是 if “进行析构”，而是变量退出作用域自动析构；lock 得到的 shared_ptr 与其他 shared_ptr 一样计入所有权。
- reserve 不增加 size；迭代器不是“必然就是裸指针”。不要通过执行未定义行为来验证悬空访问。
- const 不延长这里被借用对象的生命周期；返回引用的有效期取决于被引用对象。
